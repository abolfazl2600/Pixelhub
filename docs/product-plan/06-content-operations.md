# 06 | خط تولید محتوای بازی و پنل مدیریت

## مسئله کسب‌وکار
Pixelhub بدون جریان پایدار انتشار تصاویر، حتی با موتور Paint خوب به‌سرعت تکراری می‌شود. فایل مرحله، thumbnail، حق نشر، سختی و ابزار QA باید از ابتدا استاندارد باشند؛ پنل آنلاین در V5 وارد می‌شود.

## چرخه حیات تصویر
1. Intake: ثبت عنوان، دسته، منبع و license.
2. Draft: آپلود اثر و تصویر مرجع.
3. Convert: تغییر ابعاد، Quantization، ساخت palette و cell grid.
4. Validate: رعایت schema، تعداد رنگ مجاز، نبود خانه معیوب و تکه‌های پراکنده غیرمنطقی.
5. Preview: بازی آزمایشی همان سطح در Game Engine.
6. Review: بررسی هنری و حق‌نشر.
7. Scheduled/Published: نسخه immutable بر CDN.
8. Unpublished/Archived: عدم نمایش برای کاربران جدید بدون حذف بی‌برنامه سطح‌های قدیمی.

## محدوده نسخه‌ها
- V1: فقط فایل نمونه برای تست.
- V2: ابزار دستی تعریف level ثابت.
- V3: گالری همراه چند ده/حدود 80–120 اثر دارای مجوز (هدف غیرالزام‌آور).
- V4: کاتالوگ اولیه API اگر برای Sync لازم باشد؛ پنل کامل هنوز نه.
- V5: پنل آپلود، دسته‌بندی، کنترل کیفیت، انتشار نسخه‌دار، scheduling و rollback.
- V6: هدف اولیه 200–300 اثر قابل انتشار، رویداد و محتوای ویژه.
- V7: بارگذاری اثر توسط کاربر، گزارش، حذف، Moderation و قوانین عمومی.

## اجزای Admin در V5
- Auth مدیران و نقش‌های Owner, Admin, Editor, Reviewer, Support.
- مدیریت دسته، Tag، Pack، Level، Thumbnail و License.
- پردازش تصویر توسط Worker، با Job status و retry.
- Preview با یک Embed از engine مشترک یا شبیه‌سازی تأییدشده قرارداد.
- کنترل quality gate و انتشار با تأیید.
- Audit log برای ایجاد/ویرایش/حذف.
- Content versioning، publish at و unpublish.
- گزارش تعداد دفعات دریافت، آغاز و تکمیل مرحله.
- تنظیمات Feature Flag ساده برای دسته/محتوا.

## برنامه تولید محتوا
| مرحله | تعداد هدف نمونه | شرط |
|---|---:|---|
| V2 | 10–20 Fixture | فقط تست فنی |
| V3 | 80–120 | مناسب آلفا |
| V5 | 150+ | تست Pipeline و دسته‌بندی |
| V6 | 200–300 | هدف انتشار |
| V7 | رشد پیوسته | با تحلیل رفتار و هزینه واقعی |

این اعداد KPI برنامه‌ریزی هستند، نه تعهد یا داده بازار. کیفیت در اولویت تعداد است.

## تضمین حقوقی و حریم خصوصی
- مستندسازی سازنده اثر، مجوز و تاریخ دریافت.
- عدم کپی شخصیت‌ها/تصاویر رقبا بدون مجوز.
- تصاویر کاربر V3 خصوصی و local-only به طور پیش‌فرض.
- انتشار عمومی در V7 فقط با Consent، سیاست حذف و Queue بازبینی.
- تصاویر Upload شده به سرور ابتدا quarantine شوند؛ محدودیت حجم، فرمت و decode امن.

## کنترل هزینه
- CDN و cache صحیح برای فایل‌های immutable.
- Originalهای بزرگ در storage و Thumbnail کوچک در کاتالوگ.
- پردازش batch تصویر محتوایی در Worker، نه حین درخواست API.
- مانیتور هزینه storage، egress، worker time و rejection rate.
